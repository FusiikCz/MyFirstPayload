================================================================================
 LAB-ONLY "WORM" REPLICATION DEMO — DOES NOT WORK ON PUBLIC WEBSITES
================================================================================

This file demonstrates a replication loop exclusively in an ISOLATED LAB
against the mock website that you run locally on 127.0.0.1.

SAFETY GUARDS:
  1) Host guard: runs ONLY on "lab.local" (a non-public domain mapped in
     /etc/hosts to 127.0.0.1 in your lab).
  2) C2 = 127.0.0.1:8080 (local c2.py).
  3) Replication target = http://lab.local/index.php (your mock website).
  4) Self-replication is DISABLED BY DEFAULT: constant P contains a placeholder.
     Until replaced with a base64 payload, the worm submits harmless ads.

================================================================================
 REPLICATION LOOP ARCHITECTURE (what the demo shows)
================================================================================
  1) An infected page sends a beacon to C2 (/beacon) and waits for SPREAD.
  2) po SPREAD:
       - opens the form page (establishes a session),
       - downloads a CAPTCHA image,
       - sends it to C2 /solve (server-side OCR) and receives an answer,
       - submits a new ad containing the payload,
       - the new ad is displayed to other visitors, closing the loop.
  3) C2 /spread command -> all infected sessions replicate.

RESEARCH VALUE: measure infection growth, OCR failure rate, and rate-limit
impact — all against the mock website, with no impact on real users.

================================================================================
 HOW TO RUN IN THE LAB
================================================================================
  1) /etc/hosts:            127.0.0.1   lab.local
  2) mock website:          php -S 127.0.0.1:8000 -t . (from repository root)
  3) C2:                    python3 c2.py (prints the token)
  4) Enter the PAYLOAD below in the mock website's "Text" field
     (http://lab.local:8000/).
  5) Open the ad in a browser; it sends a beacon to C2.
  6) Trigger replication: curl "http://127.0.0.1:8080/spread?token=<YOUR_TOKEN>"
  7) Dashboard: http://127.0.0.1:8080/?token=<YOUR_TOKEN>
